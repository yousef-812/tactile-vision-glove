## 🟡 ثانياً: ما سيتم عمله في الخطوات القادمة (What Needs to Be Done)

تم تقسيم الخطوات القادمة إلى 3 مراحل رئيسية للعمل بدون خامات أولاً ثم التجميع الفعلي:

### 🚀 الخطوة 3: تطوير تطبيق الموبايل للمرافق (Companion Mobile App)
* **الهدف:** بناء النواة البرمجية لتطبيق الموبايل (Flutter/React Native) المخصص لمتابعة حالة الكفيف.
* **المهام المطلوبة:**
  - تصميم واجهة عرض حالة البطارية والاتصال بالبلوتوث (BLE).
  - محاكاة إرسال واستقبال موقع الكفيف الجغرافي (GPS Location Mocking).
  - برمجة إشعار الطوارئ ولحظة السقوط (SOS Trigger UI) وربطه برسائل SMS.

### 🔗 الخطوة 4: ربط كاميرا الـ AI بمحاكي Wokwi (الربط المباشر)
* **الهدف:** جعل حركة يدك الحقيقية أمام كاميرا الكمبيوتر تتحكم فوراً بلمبات Wokwi الافتراضية أونلاين.
* **المهام المطلوبة:**
  - إعداد منفذ تسلسلي افتراضي (Virtual COM Ports) باستخدام `com0com`.
  - تحديث كود الـ Python ليقوم بإرسال إشارة الـ PWM التسلسلية (`PWM:t,i,m,r,p`) مباشرة عبر المنفذ.

### 🛠️ الخطوة 5: تجميع العتاد المادي والقفاز الحقيقي (Hardware Assembly)
* **الهدف:** الانتقال من شاشات المحاكاة إلى القفاز الفعلي.
* **المهام المطلوبة:**
  - شراء العتاد الموضح في قائمة القطع (BOM).
  - تثبيت المحركات والأسلاك داخل القماش بشكل محمي ومريح للكفيف.
  - توصيل الـ ESP32-S3 بالكمبيوتر ورفع كود الـ C++ النهائي عليها.
  - بدء الاختبارات الميدانية مع فارس (Blindfold Test).
